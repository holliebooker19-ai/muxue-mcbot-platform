## 目标

1. **Agent 接入（主线）**：同一个 ServerBody 和同一组 MCP 工具，可以选用 Claude Code、Codex、DeepSeek Harness（dsh）或原生 API。dsh 的需求最高，优先做。
2. **Mod 适配：接口加示例**：核心模组开放适配接口，我们自己做 2～3 个示例；其他 Mod 由使用者按接口自己适配。适配器做成装上就能用的附属模组。
3. **多版本、多加载器**：按需求再做，不提前铺开。

## 还没解决的

- **持续陪挖**：10-06 查清 `COMPANION_OUT_OF_RANGE`（掉落物滑出半径就被拒绝拾取）并修正，程序矩阵 10 个场景连续两轮通过，见[陪挖验收](archive/companion_mining_validation.md)。真实模型陪挖还没跑，等第 3 步用户验收后才算交付。
- **Node 24.15**：在 Windows 上有一次没定位的原生退出（0xC0000409），目前用 Node 24.19 加 `-NodePath` 绕开；绿色版带的是官方 Node 24.21.0。
- **评审遗留**（见 [评审修复记录](archive/boundary_review_fixes.md)）：R5（Mod 适配分派入口）第 7 步已做、R7（Agent 会话入口拆分）第 4 步已做；R6 只做了背包物品的观察降级，容器格子和地上物品还没有。
- **托管途中死亡**：10-10 起 WebUI 启动的托管（`start-server-play.mjs --wait`）会等角色复活后自动重新接管，并告诉 Agent 自己死过；命令行不带 `--wait` 时照旧要重新启动托管（启动时会自动重生）。10-11 试玩发现死后超过 1 秒才复活会先下线再上线，已修成原地复活；复活后告诉 Agent 死因和死的地方，并提示接上断开前的跟随和保护（离线测试通过，用户实测不再退出、加入；隔离服复活脚本已改成死后等 3 秒再复活，还没跑）。
- **驱动器和提示词在变大**：`scripts/companion.mjs` 约 1560 行，启动提示词二十多条规则，每加一个能力就加一句；工具约 60 个，小模型容易选错。还没定怎么拆。
- **实测脚本靠本地夹具**：隔离服实测依赖本机存档、备份和端口，没有 CI。
- **建筑**：10-09 做完服务端执行（8i），屋顶最窄的屋脊和墙角竖放的柱子会剩一些；不会搭脚手架走廊，大房子要多叫几次。
- **单人模式**：10-06 定为「开局域网后才能接管」，绕开暂停问题，开发客户端实测通过，见[单人模式](singleplayer_design.md)。待用户在自己的实例里验收；不开局域网的暂停处理没做。

### 2026-10-11 试玩反馈和排期

用户在自己的单人实例（局域网，Claude）连续试玩。下面“实测”指用户在真实游戏里看到的结果。

当时已修好、后来都已提交并推送的（8843e77、8c6b4f2）：
- **死后会退出重进**：原版玩家死后 1 秒被移出世界（`KILLED`），以前服务端把它当成身体没了，先下线再读死亡存档上线。改成原地复活；`hello.lastDeath` 记死因和位置，重连后驱动器马上告诉 Agent 死因和断开前的跟随／保护（运行端 `posture-<名字>.json`）。实测通过（不再退出、加入）。
- **弓射不出、拉弓动画闪烁**：保护接管身体前的“身体忙”检查把保护自己拉的弓也算成在用物品，下一 tick 就收回放下，永远拉不满。改为保护战斗中自己的弓和盾不算忙（`GuardDuty.bodyFree`）。实测能射出（实服第一次）。
- **弓的诊断**：保护状态多了 `draws`、`lastEnd`、`lastDrop`、`lastBreak`，拉了弓没射出时服务端日志写一行 `MCBOT guard: drew the bow …`。
- **怪躲在方块后面打不中**：以前判断“能射”看眼睛到眼睛的直线，瞄准却瞄身体中心；改成依次试中间、胸口、头，按原版箭的飞行逐 tick 模拟，先碰到怪而不是方块才射。离线测试通过，真实游戏没试。

同一轮实测通过的（已推送的 512ef99 里）：跟随中砍树、丢给 Bot 的物品会通知、看得到玩家和生物的装备（含附魔、耐久）、忙时先回“收到，正在忙”、跟随中换装备不停下。没测：叫停后不点名接着说、没武器时空手还手。

待做，按顺序：
1. **收到好装备自己换上**：收到装备时比较身上同部位的（护甲值、附魔、耐久），更好就穿上并说一声。
   - 状态：✅ 离线完成、真实游戏未验证（10-11）。服务端只读能力 `assess-armour` 判断哪件更好（`ArmourChoice.java` 唯一一份），运行端 `gift-gear.ts` 在 `gift` 事件发出前穿上并写“已换上 X（替下 Y）”；正在忙时不打断，事件写“可以换上 X，但正在忙”。详见[协议](server_body_protocol.md)的 `assess-armour`。
2. **盾**（已实现，离线测试通过，待隔离服实测）：近战试玩没见举盾的原因查明：保护自己举的盾被“身体忙”检查当成别人在用物品，下一 tick 就被收回（`bodyFree` 修复之前），与弓同因；修复后还没在真实游戏里看过。条件本身（等冷却、怪正打自己）没改，只加了 `shields` 计数和 `lastShield`。新增：苦力怕点燃（快炸）、按剩余引信和爆炸范围估算跑不出去时，原地举盾面朝它，爆炸后放下；跑得出去照旧撤退（不举盾，举着盾不能冲刺）。
3. **坐下（B4）**（已实现，离线测试通过，待隔离服实测）：新工具 `sit`（8 格内最近的空座位或指定坐标，空手右键，确认骑上座位实体才算成功）和 `stand-up`；核心 `SeatAdapter`，森罗厨房附属登记椅子和厨师凳（只认 1.6.0）。坐着时会动身体的动作报 `SEATED`，要先 `stand-up`；坐下结束跟随、保留保护，有保护时，保护要出手了（和保护同一套判断：以玩家为中心、保护半径内有要打的怪）Bot 就站起来打，打完不坐回去；坐下不另设范围（10-11 用户要求和保护一致，不加魔法数字）。原计划：核心加座位适配和 `sit`／`stand-up`，森罗厨房的椅子、凳子登记为座位；坐下结束跟随、保留保护。
4. **局域网创造模式**（已做提示，离线验证）：用户开局域网时选了创造，原版会把所有加入的玩家（包括 Bot）强制成创造，服务端只接管生存的身体，于是 Bot 反复进出。用户决定（10-11）：先不支持，只提示。WebUI 托管页写明“目前只支持生存模式（开局域网时游戏模式选生存）”；接管因为不是生存模式失败时，托管日志里给出同样的提示。以后要做的话：开局域网强制的游戏模式不是生存时，Bot 登录后改回生存（只改 Bot，用户自己照样创造）。Bot 本身用创造模式干活不支持，原因见下。
5. **接管失败的原因写进 WebUI 托管日志**（已做，离线验证）：这次 Bot 反复进出，日志里一个字都没有。原因：运行端接管失败只写 stderr，服务端的拒绝原文也被丢掉（只给 Agent 看错误码）。现在托管运行端接管失败时往 `activity-<名字>.jsonl` 写一条 error（`client-runtime/src/claim-failure.ts`）：不是生存模式给固定中文提示，其他原样写错误码和服务端原文（去控制字符、限 200 字，只进本地日志，不给 Agent）；驱动重试时同一句 10 分钟内只写一次。
6. **游戏运行时 WebUI 插件页不许换 jar**：这次换 jar 时游戏已经在加载模组，内存里还是旧代码。
   - 状态：✅ 完成（10-11，70d77b1）：安装前和放文件前各查一次游戏进程，加载中也算；10-11 凌晨用户实测主菜单、世界中都拦住。
7. **弓：站位不好时挪一步**（已实现，离线测试通过，待隔离服实测）：射不中时在脚边 1 到 4 格的八个方向里找一个能站、箭射得到怪的最近点走过去再射；不出保护范围、每秒最多找一次、一场最多挪 6 次、走不通就放弃。状态 `repositioning`，`lastReposition` 写结果。
8. 之前排的（排在后面）：弩、驱动器重启这一步（工具服务随身体断开退出，几秒空档）。“被骷髅射死时威胁列表是空的”已删：用户判断是当时远处威胁没算进去的老问题，10-11 晚上长时间实测没再出现。

- 10-08 评估（用户问写了这么多附属模组，多版本好不好做）：
  - **附属模组不是难点。** 每个都很薄（入口一个类，编译只依赖我们的 API），换 Fabric 只是换入口和元数据。花时间的是跟着被适配的 Mod 走：适配锁定精确版本，每个新版本都要重新实测；森罗厨房和 SB 用反射，对方改名就要跟着改；对方没出那个版本，那个适配就不出。YSM 只转发指令，最不容易坏。估计每个版本每个适配几小时到一天，大多是测试。
  - **核心是大头。** 换 MC 版本：核心大量用原版内部实现（寻路、发包、菜单格子、配方、物品组件），小版本之间也常改，要逐处修再跑全部实测。换 Fabric：8l 已经把加载器代码隔离到登记的几个文件里，但那里用了不少 NeoForge 事件（受伤、横扫、聊天、踩耕地、吃完东西等），Fabric 没有一一对应的，要写 mixin，实打实几天。
  - **Node 运行端、WebUI、驱动器基本不用动**，协议不变就行。
  - **寻路**（10-09 用户问是不是完整移植了原版、能不能快速迁移）：不是移植，是运行时直接调用当前游戏的原版类（`PathFinder`、`WalkNodeEvaluator`，按一个站在 Bot 位置的僵尸算路线），所以算路的规则跟着游戏版本走，不用自己维护。自己写的部分：在原版节点上加跳沟、丢掉超下落上限的节点、限制范围（`RouteEvaluator`，几十行）；照路线走的驱动（转向、起跳、到点判定，照原版 `PathNavigation`／`MoveControl` 的做法重写，因为 Bot 是玩家，玩家没有寻路组件）；开门、游泳上岸；长途走的粗路线（`SurfaceRoute`，只用高度图和方块状态）。这些都不用 NeoForge 的接口（构建时的加载器检查管着），换 Fabric 时用官方映射名字一样。迁移的工作量在原版内部接口随版本改名、改签名（例如 1.20.5 起 `BlockPathTypes` 改名 `PathType`，判断格子类型的方法参数也改过）：1.21.x 之间估计每个版本改几处到半天，主要时间花在重跑寻路、跳沟、长途走这几套实测。没有在任何其他版本上编译过，以上是估计。
  - 做法（待定）：先把构建拆成共用代码加每个版本一层薄的差异代码，先加一个更新的 1.21.x NeoForge，跑通全部实测，再做 Fabric。
- 宣传网页加自己的安装器：网页介绍项目、按版本列出已适配的组合；安装器选好版本后，把我们的模组装进用户已有的启动器实例（Prism、HMCL、PCL 等），并装好想用的模组。我们只托管自己的模组；别人的模组按许可证从 Modrinth、CurseForge 官方源下载，不重新分发；不做启动器本身（不分发游戏本体、不处理正版登录）。
