## ServerBody 长期记忆方案（2026-10-12，用户同意；①～③已实现，④未做）

### 要解决什么

玩家看到的效果：
- 换会话、隔天再玩，Bot 还记得玩家的称呼和喜好、一起做过的事、没兑现的约定（“明天帮你盖仓库”）。10-12 晚试玩时玩家问“你还记得我们之前干了啥吗”，Bot 只能答记不清。
- 做到一半换了会话能接着做，不重新问（10-11 试玩：砍到 64 段换会话，新会话不知道做到哪了）。
- 以后的自主性要记得昨天的安排和玩家说过的话。

2026-10-12 之前的情况：ServerBody 上下文到上限先压缩，压缩不了、空闲超过续接窗口（默认 50 分钟）或隔天再开就换新会话，什么都不带。旧 Mineflayer 路径有一整套记忆（`mcp-server/src/memory.ts`、`tools/memory-tools.ts`：分层 Markdown、程序自动记日志、`memory-note`／`memory-recall`／`memory-write`、躺床和下线时整理、每段字数上限），但只在 `--body mineflayer` 时开。

### 别人怎么做（10-12 调研摘要）

派 Haiku 查了 Voyager、斯坦福小镇（Generative Agents）、Mindcraft、GITM、MemGPT／Letta、Mem0、Zep、LangMem、SillyTavern、Claude Code、Claude.ai、ChatGPT 等；Mindcraft 的摘要上限和 Claude Code 的加载量我抽查过原文，ChatGPT、Cursor、Replika 只看到搜索片段。
- 分层：最近对话、常驻的小档案或摘要、可查的完整记录（MemGPT、Mindcraft、Mem0、Zep）。
- 谁写：模型边聊边自己写（MemGPT、Claude Code、Claude.ai），或后台另一个模型抽取整理（Mem0、Zep）。
- 怎么取：少量重要的一直放在提示词里（Letta、ChatGPT、Claude Code 的 MEMORY.md 前 200 行），大量旧事按需查（向量、关键词、时间）。
- 防膨胀：合并、替换，原始记录保留但不加载（MemGPT 递归摘要、GITM 满 5 条合并、Mem0 每条只做新增／更新／删除／不动）。
- 已知问题：检索漏掉、给记忆添油加醋、记忆越多行为越不可信（斯坦福小镇作者自述）；DeepSeek-V3 抽取事实约 25% JSON 格式错（第三方论文，只看了摘要）。

### 分层

| 层 | 放什么 | 谁写 | 怎么用 |
| --- | --- | --- | --- |
| 0 交接单 | 正在做的任务和进度、跟随还是等待、最近十几句聊天 | 程序从运行端状态生成，不经模型 | 换会话时塞进新会话 |
| 1 常驻档案 | 人设（只读）、玩家档案（称呼、喜好、讨厌的）、没兑现的约定、最近几天的摘要 | 整理时写，每段有字数上限（沿用旧 `SECTION_LIMITS`） | 每次开会话放进提示词 |
| 2 日志 | 每天的原始事件、聊天，加模型自己记的主观的事 | 程序自动记，模型用 `memory-note` 补 | 不加载，`memory-recall` 按关键词和时间查 |
| 3 今日安排 | 当天想做的两三件事 | 早上模型列 | 给自主性用 |

### 定下来的做法

1. 记忆放在运行端，三家 Agent 用同一套代码和格式，记忆目录相同就共用、换 Agent 不丢（10-13 注：记忆目录留空时 Claude 用仓库的 `memory/`，Codex、dsh 用 `runtime/<agent>-memory`，所以默认不共用；要共用就在 WebUI 里给它们填同一个记忆目录，角色目录都按游戏名小写）；不用各家自带的记忆（Claude Code 的按账号存，Codex、dsh 没有）。
2. 先不用向量库和知识图谱：本机不多一个嵌入模型；陪玩的量小（小克整理后几段合计约 1.4 万字）；中文按关键词加时间查先够用，查不到再加。
3. 整理在单独的一次性会话里做：同一 Agent 和账号，只给记忆工具不给游戏工具，不打断正在玩的会话；每条只能新增、更新、删除或不动，并注明依据的日志条目。时机：躺床、玩家下线、换会话前。每次多花一轮模型调用，一天一两次（用户同意）。（10-13 注：“一天一两次”是估计，不是程序规则。实现里只有躺床触发的要和上次整理隔够 30 分钟（`--consolidate-floor-min`）；玩家都下线、换会话、启动时只要有没整理的日志就整理，没有每天的上限。换会话的整理在旧会话结束后开始，和新会话同时跑。）
4. 只记确认过的事：游戏事实、玩家亲口说的、角色感受分开写，没有证据的不写成经历（沿用 soul_system.md）。
5. 归属：玩家档案多个角色共用；地点和世界现状按世界分；回忆、约定、摘要按角色分（同旧设计的 `shared/` 和 `<角色>/`）。10-13 改：约定、摘要、日志、整理进度也按世界分（`<角色>/worlds/<世界>/`），回忆和玩家档案跨世界、每行注明世界，见下面“实现情况”。
6. 原始日志一直留着（量小），WebUI 能删；WebUI 记忆页先只能看和删，改以后再说。

### 分步

| 步 | 内容 | 解决什么 |
| --- | --- | --- |
| ① | 交接单（只用程序） | 换会话不知道在干什么、做到一半重新问 |
| ② | 旧记忆搬到 client-runtime：日志自动写、`memory-note`／`memory-recall`、开局加载常驻档案；WebUI 记忆页只读 | 隔天记得称呼、喜好、约定 |
| ③ | 单独会话整理 | 记忆不越积越多 |
| ④ | 今日安排 | 接上自主性 |

### 实现情况（2026-10-12，①～③）

接口细节见[协议的长期记忆一节](server_body_protocol.md#长期记忆运行端和驱动器2026-10-12)。和上面写法的出入：

- 复用而不是复制：`MemoryStore` 整个搬进 `client-runtime/src/memory.ts`，`mcp-server/src/memory.ts` 只转出（`mcp-server` 构建时先构建运行端），一份代码两条路径用，旧测试原样通过。驱动器不能引用 `scripts/` 以外的模块（打包规则），所以上限放进 `client-runtime/memory-limits.json`，运行端、驱动器、WebUI 读同一份，打包时一起带上。
- 约定没有单独一段，沿用旧的 `goals`（提示词里标题叫「约定和想做的事」）；玩家档案的上限用 `goals` 的（同是开局常驻的短清单），没有另起数字。
- 世界现状从 `shared/world.md` 改为按世界的 `shared/worlds/<世界标识>.md`；旧 Mineflayer 路径没有世界标识，仍用 `shared/world.md`。
- 按世界隔离（10-13，开发新功能前必须先处理的第 1 项）：①～③ 只有世界现状按世界分，到了新世界会提旧世界的房子、去兑现旧世界的约定。现在约定、摘要、日志、整理进度放在 `<角色>/worlds/<世界标识>/`，开局加载、`memory-recall`、整理都只看当前世界；人设、回忆、玩家档案跨世界，整理写进回忆和玩家档案的每行依据前自动加世界标识。WebUI 记忆页按世界分开列约定、摘要和日志。`memory-recall` 不查别的世界的日志：跨世界的事靠整理进回忆。那时还没有真实记忆数据，没做迁移。
- 交接单不管有没有人设都发：它只用运行端已有的状态文件，不碰记忆目录。
- 局域网关游戏（断开）不立刻整理，下次启动时发现有没整理的日志再整理，和新会话同时开始。
- ②里 WebUI 记忆页写的是只读，按“定下来的做法”第 6 条做成能看、能删一行或一天（`scripts/webui-memory.mjs`），删前备份到 `runtime/memory-backup/`，不能改。
- 整理会话改段落用 `memory-write` 的新增／更新／删除，每条新增和更新写成 `- [事实|玩家说|感受] 内容 〔日志游标〕`（回忆和玩家档案的行由程序加上世界：`〔<世界> <游标>〕`）；旧的整段覆盖写法只留给旧路径。
- 工具：托管时给模型 `memory-note`（记一句，最多 300 字）和 `memory-recall`（查这个世界的日志，默认 40 条、最多 200 条）；整理会话只有 `memory-context`（读当前记忆）、`memory-recall` 和 `memory-write`（一次最多 64 条改动）。每段的字数上限、开局带几行日志、写锁的等待和过期时间都在 `client-runtime/memory-limits.json`，运行端、驱动器、WebUI 读同一份。
- 还没经过真实模型和游戏：整理质量、交接单在真实换会话时够不够用、三家 Agent 另起会话的额度消耗，要等试玩。
